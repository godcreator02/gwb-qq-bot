## 背景与目标

机器人通道 0.1.0 已上线（QQ 私聊 → ZCode 派任务 → 结果回推）。本方案回答「通道之上长什么」：
随手记、MR 流程、主动推送，以及多人（课题组）怎么共用这套形态。定稿过程中否掉了三个过度设计
——指令注册框架、通用 Gitea 审阅代理、bot 间消息传递——理由见轨迹区的对应卡片与本文铁律。

## 全景图

```
                    每个成员的电脑（互不依赖，无群、无 bot 间通信）
┌─────────────────────────────────────────────────────┐
│  gwb 工作台                                          │
│   ├─ gwb-qq-bot ── 私聊通道（裸文本全进 ZCode 会话）    │
│   │    ├─ 消息进 → agent 判断意图（不设指令系统）       │
│   │    └─ 消息出 ← 被动回复 + pushToOwner 主动推送      │
│   ├─ ZCode 桌面端 ── 连 gwb MCP，能调全部命令          │
│   │    （bn-journal / gitea.http / collab.* …）       │
│   └─ gwb-collab ── 协作站身份与流程（MR 监控加在这）    │
└──────────────────────┬──────────────────────────────┘
                       │ 轮询 + API（各用各的令牌）
                    Gitea（MR、任务、协作仓——事件的唯一正本）
                       │ 邮件通知（兜底）
                    每个人的手机
```

三条铁律：

1. **通道不做机制**：qq-bot 只管消息进出与推送，不认识任何「功能」；无指令注册、无通用代理
2. **功能长在应用里**：日志归 bn-journal、MR 归协作站线；能力以 gwb 命令存在，agent 见机调用
3. **bot 只听主人的**：每 bot 单人白名单；合并以主人自己的 Gitea 身份执行，不发明权限模型

## 接口事实（官方原文 + 2026-10-05 沙箱实测）

| 规则 | 数值 | 依据 |
| --- | --- | --- |
| 被动回复窗口（单聊） | 60 分钟，每条消息回 4 次 | 官方接口页原文；窗口已日常验证，4 次待探针 |
| 主动消息发送方 | 个人身份证认证 10 条/秒；未认证 5 条/秒且 30 条/分 | 官方接口页原文 |
| 主动消息接收方 | 每人每分钟 20 条、每天 1000 条 | 同上 |
| msg_seq | 与 msg_id 联合去重，重复组合被拒（错误码 40054005） | 官方原文；插件递增写法正确 |
| 链接过滤 | 未报备域名（内网 Gitea）必被吞，播报纯文字 | 官方规则 |
| 用户开关 | 可在 QQ 客户端关闭「接收主动消息」，推送需留降级 | 官方规则 |
| 互动召回（is_wakeup） | 30 天 4 周期各 1 条，与普通主动消息是两回事，不用 | 官方原文（「每月 4 条」误传的源头） |

连发 8 条主动消息全部成功的原始输出在 `probes/`，结论卡片见轨迹区。搜索摘要把互动召回误传成
「每月每用户 4 条主动消息」，本项目按原文与实测为准。

## 分部设计

**qq-bot 通道（gwb-qq-bot 仓）**：本期唯一代码改动是加 `ctx.gwbQqBot.pushToOwner(text)`
（主动私聊推送，白名单那个人为唯一收件人；失败不重试、记日志）。其余维持现状：裸文本=进 ZCode
会话，三条管理指令（/帮助 /状态 /新会话），被动回复按窗口选路。版本升 y。

**日志随手记（零开发）**：QQ 自然语言（「记一下：……」）→ ZCode 调 bn-journal 命令写当日日志块
→ 回执。flomo 弃用，收集命令进观察期后退役，历史数据不动。若一句话也走一轮 GLM 觉得贵/慢，
再加轻分流层——有痛再长。

**MR 流程（归协作站线，独立立项）**：gwb-collab 加 MR 监控——轮询「我负责的仓」，新 MR 在
负责人电脑上拉分支跑检查，pushToOwner 私聊推送摘要（纯文字），Gitea 邮件兜底；负责人自然语言
回复，agent 调 gitea 命令以本人身份执行。第一版只播报、人开口才合并；跑顺两周后开放直合档
（机械检查全绿 + 只碰文档的小改动）。多人形态：每人注册自己的实名 bot（一 bot 一 home，不可共用）、
各自电脑常驻、沙箱终态（测试用户=本人）。测试用一个账号建两个 bot + 两个隔离 home 模拟 A/B。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| ZCode 桌面端是通道单点：它不开，机器人只剩三条管理指令 | 自用可接受；多人推广时向成员讲清常开要求 |
| 每条消息一轮 GLM 额度 | 单人可忽略；痛了加轻分流 |
| 负责人电脑离线，流程停在他那 | Gitea 积压 + 邮件；人急了上网页手动合 |
| 用户关闭「接收主动消息」 | 推送静默失败记日志；拉模式天然兜底 |
| 30 天不交互后的冷启动推送未实测 | 日常活跃无此场景；降级已有；择机实测 |
| 腾讯内容审核 | 项目内容低风险；链接必吞已知 |

## 待验证清单

1. **群内 bot 互见性**：两个 bot 同群，A 发消息 B 收不收得到事件。当前方案不依赖它；若官方支持，
   未来可选「群内 bot 对话给人围观」的形态；若不支持，「零 bot 通信」成为官方定论
2. **冷启动主动消息**：30 天不交互后普通主动消息是否受限（互动召回机制明确可发，普通通道未测）
3. **被动每消息 4 次上限**：需代码探针（同 msg_id 连发递增 msg_seq 观察第几条被拒）
