**本页回答**：这个项目里反复出现的词各指什么。

**openid**
QQ 开放平台给用户的标识，每个机器人看到的同一个用户 openid 各不相同，不是 QQ 号。
白名单与聊天的 id 都建立在 openid 上，首次配置从 `qq-bot.status` 的 `recentRejected` 里抄。

**聊天**
一个私聊或一个群，聊天表里一行，id 是 `c2c:<openid>` 或 `group:<群 openid>`。绑定、会话、在跑的一轮、排队都按聊天分开。

**一轮**
一条任务从派出到收尾：派给执行端、agent 做完回报（或懒检查发现做完却没回报）、结果发回原聊天。同一个聊天一次只有一轮在跑。

**本轮编号**
派出时生成、写在任务说明末尾的编号，agent 回报时带上它，qq-bot 靠它对上是哪个聊天的哪一轮。只用来对号，不当凭证。

**懒检查**
这一轮还没回报，而人发了 /状态 或又来一条消息时，qq-bot 才问一次执行端做完没有；平时不轮询。

**执行端适配层**
qq-bot 私有的模块：把「开一轮、问一次做完没有」翻译成 ZCode、Claude Code 各自服务的方法，每个执行端一份实现。

**被动回复**
带 msg_id、挂在一条用户消息上发出的回复，有窗口与次数：群聊 5 分钟内每条消息 5 次、单聊 60 分钟内 4 次。
插件的回执与结果默认都走这条路。

**主动消息**
不带 msg_id、直接发给用户的消息，受官方频控与用户「接收机器人主动消息」开关限制。
插件只在单聊被动失败时用它，以及给主人发通知；群里不用。

**引用**
回复里带的 `message_reference`，QQ 里显示成引用某条消息。和被动回复挂在哪条消息上是两回事：/状态 补发的结果挂在 /状态 上，引用的是派出那一轮的任务消息。
主人通知不引用任何消息。

**沙箱**
历史接入环境，API 走 sandbox.api.sgroup.qq.com。新版后台的开发体验号码使用当前官方 api.bot.qq.com，
插件设 sandbox=false；不要把开发体验号码与历史沙箱环境当成同一个概念。
