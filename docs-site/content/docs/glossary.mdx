定义只写概念；具体的命令、类型和文件写在每条后面指的那一页，在那里钉码。

## 私聊与派任务

**私聊**
一个用户和机器人之间的单聊，聊天表里一行，代码与回执里也叫「聊天」。绑定、各任务组的状态、没送达的结果都按私聊分开。插件不处理群聊。见[聊天表](/docs/dispatch/chat-table)。

**任务组**
一个工作区加一个执行端，用一个斜杠命令触发。每个私聊里每个组各有一份会话、在做的一轮和队列：同一组一次做一件，不同的组可以同时做。见[派任务](/docs/dispatch)。

**默认组**
每个私聊都有的那个任务组，没有命令，接收不以「/」开头的消息；它的工作区与执行端由这个私聊的绑定决定，主人私聊没绑定时按设置算。回执里叫它「默认」。

**组命令**
触发一个任务组的斜杠命令。去掉斜杠就是组名；第一段和它完全相同、后面跟着正文，正文就是交给这一组的任务。见[一条消息分到哪](/docs/dispatch/routing)。

**直接命令**
别的插件注册的斜杠命令：插件当场处理、回一句话，不排队、不开会话、不派给 agent。

**保留命令**
帮助、状态、开新会话三个命令，谁都不能注册同名的命令。

**命令登记的组**
agent 用命令登记、存在聊天表里的任务组，给自己常用的目录用，不用为它写插件。和它相对的是插件注册的组，插件卸载时自动撤掉。

**绑定**
给一个私聊设默认组：在哪个目录、交给哪个执行端、回执里叫什么、要不要附加要求。

## 会话与一轮

**会话**
执行端那边的一段连续对话。一个组的下一条任务默认接着用这个会话，空闲太久、换了执行端或工作区、或人要求时才开新的。

**会话行**
回执第二行「会话 xxxx · 第 N 轮」：会话号的末 4 位和这个会话的第几轮，手机上看得出是接着做还是新开的。

**一轮**
一个私聊的一个任务组里的一条任务，从派出到收尾：派给执行端，agent 做完回报（或懒检查发现做完却没回报），结果发回原私聊。

**本轮编号**
派出时生成、写在任务说明末尾的编号，agent 回报时带上它，靠它对上是哪个私聊哪个组的哪一轮。只用来对号，不当凭证。

**懒检查**
这一组这一轮还没回报，而人问状态或又往这一组发了一条消息时，才问一次执行端做完没有；平时不轮询。

**执行端**
真正干活的 agent 所在的程序（ZCode 或 Claude Code），由对应的 gwb 插件做成服务。

**执行端适配层**
qq-bot 私有的一层：把「开一轮、问一次做完没有」翻译成各执行端服务的方法，每个执行端一份实现。

## QQ 这一侧

**openid**
QQ 开放平台给用户的标识，每个机器人看到的同一个用户 openid 各不相同，不是 QQ 号。白名单与私聊 id 都建立在它上面，首次配置从最近被拒的记录里抄。见[连接与收发](/docs/qq)。

**被动回复**
带着一条用户消息的 id 发出、算作回复那条消息的消息，有窗口与次数：单聊 60 分钟内每条消息 4 次。回执与结果默认都走这条路。

**主动消息**
不针对任何一条用户消息、直接发给用户的消息，受官方频控与用户「接收机器人主动消息」开关限制。只在被动回复发不出去或过了窗口时用，以及给主人发通知。

**引用**
回复里带的引用信息，QQ 里显示成引用某条消息。和被动回复算在哪条消息上是两回事：补发的结果用状态查询那条的窗口，引用的是派出那一轮的任务。主人通知不引用任何消息。

**没送达的结果**
被动、主动都发不出去的结果，连同组名和要引用的消息记在私聊里，人发状态查询时补发。

**主人**
这台机器的主人在本机器人上的 openid：主动通知的唯一收件人，主人私聊没绑定时默认组按设置派出。

**「/」指令面板**
私聊机器人时在 QQ 客户端里输入「/」弹出的指令列表；点一条只是把它填进输入框，人接着写正文再发。qq-bot 把注册的命令自动同步进去，只给白名单里的人看。见[连接与收发](/docs/qq)。

**沙箱**
历史接入环境，接口地址和正式环境不同。新版后台的开发体验号码用的是正式接口，不要把开发体验号码与历史沙箱环境当成同一个概念。
