源码在 `plugins/qq-bot/src/dispatch/`。方向是人 → 工作台 → agent → 人：私聊里的一句话交给 claude-agent 在某个任务组的目录里做，这一轮结束后把 agent 的最后一条回复发回原私聊。
`chat-rounds.ts` 是中心，别的文件是它用的纯函数（分发、会话选择、参数校验）和插件注册表。它只经连接与收发导出的函数收发消息，不 import 通知。
连接与收发不认识任务组：收下的每条分到哪、发出的每条是哪一种（回执、结果、补发、指令的回答、没派出的说明）、哪个组第几轮，都由这里作为参数传过去，记进连接与收发的[消息记录](/docs/qq)。

## 任务组

一个任务组对应一个工作区，在每个私聊里各有一份会话、在做的一轮和队列。同一组一次只做一轮，后来的消息排在这一组自己的队列；不同的组各自排队、可以同时做，两个组指向同一个目录也照样同时做，不锁工作区。

组有三种来源：

| 来源 | 怎么来 | 谁能用 | 存在哪 |
| --- | --- | --- | --- |
| 默认组 | 每个私聊一个，由 `qq-bot.bind` 设；主人私聊没绑时用设置 `default-workspace` | 只有这个私聊 | 绑定写在私聊行里，主人的默认绑定按设置现算 |
| 命令登记的组 | agent 调 `qq-bot.group.add` / `remove` | 白名单里的每个私聊 | 聊天表 |
| 插件注册的组 | 别的插件调 `gwbQqBot.registerTaskGroup` | 白名单里的每个私聊 | 服务对象上，插件卸载或重载时撤掉 |

命令登记的组存在聊天表、不放进设置：设置项只支持字符串、数字、布尔与字符串列表，存不下一个组的几个字段，见[组登记存聊天表](/trajectory/2026-10-08-own-groups-in-chat-table)。
一个组的定义（命令登记与插件注册同一个形状；默认组没有命令，其余字段来自绑定）。组里不写执行端和模型：任务一律交给 claude-agent，用哪个模型是 claude-agent 自己的设置 `default-model`，见[执行统一交给 claude-agent](/trajectory/2026-10-15-claude-agent-only)：

## 命令名

命令以 `/` 开头、不含空白，去掉斜杠后汉字等非 ASCII 字符算 2、其余算 1，总长不超过 16。QQ「/」指令面板的条目名含斜杠最长 14，更长的命令照常能用，只是不进面板，这条规则不因面板改变。
`/帮助`、`/状态`、`/新会话` 是保留命令，谁都不能注册；和已有的任何命令重名（不论对方是哪种来源）直接报错，不覆盖、不自动改名。去掉斜杠就是组名，`/新会话 <组名>` 用它：

## 会话

下一轮接着用这一组的哪个 claude-agent 会话：

- **默认复用**：会话记着工作区，和组现在的工作区对得上、空闲没超时，就接着用
- **空闲超时开新会话**：这一组上一条任务开始或收尾以后，过了组的 `idleHours`（不给就用设置 `idle-hours`，缺省 6）才来下一条，就开新会话，回执里写「已开新会话（空闲超过 N 小时）」
- **换了工作区开新会话**：改绑、组的定义改了都算
- **手动开新会话**：`/新会话` 清掉默认组的会话，`/新会话 <组名>` 清掉那一组的；在做的那一轮做完照常发回

设置 `idle-hours` 不是正数时派任务报错、这条不派出，不替它改值。定了开新会话就当场清掉旧的：派出失败以后上一条任务的时间已经刷新，不清的话下一条会接回旧会话：

## 一轮怎么走

**入队**：收下消息、分发、进这一组的队列在同一步里做完（见[连接与收发](/docs/qq)的去重），然后让这一组往前走：没有在做的一轮就取下一条开一轮；有就回「已接收，排在第 N 个」。
回执第二行报这个私聊此刻在做几件、是哪几组、各组一共排队几条，如「现在在做 2 件（默认、mmc），排队 1 条」：一个 QQ 私聊里常有好几个组同时在做，看得出这一条前面还压着多少，见[回执改报任务数](/trajectory/2026-10-16-receipt-shows-workload)：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="203-216" hash="062ce35ac93d" blob="6a2e3cf91455" */}

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="611-616" hash="6eeff621f7f9" blob="6a2e3cf91455" */}

**派出**：从这一组的队列取下一条，定下会话，记下本轮编号、发言人、工作区和触发消息，调 claude-agent 的 `create`（开新会话）或 `send`（接着用），拿回会话号和它那边的轮数存进这一轮，回「已接收，开始做」，第二行同上；空闲超时开了新会话的再加一行「已开新会话（空闲超过 N 小时）」。
没装 claude-agent、派出失败，都把原话带组名回给私聊、这一轮作废、接着派这一组的下一条，不留「派出未确认」这种要人手工解除的状态；接着用旧会话时失败，回复里提示发 `/新会话`：

## 服务的两个注册方法

`registerTaskGroup`、`registerCommand` 交回撤掉注册的函数，写法和 `gwbSkills.register` 一样：调用方包在 `ctx.effect` 里，插件卸载或重载时自动撤掉；撤掉旧注册不会撤掉之后同名的新注册。
命令名不合规则、和已有命令重名、工作区不是已存在目录的绝对路径、带了认不出的键都当场抛异常；不检查 claude-agent 装没装，派任务时没装就把原因回给私聊。
注册表放在服务上，QQ 还没连上时也能注册；注册、撤掉都通知监听者（`onChange`），装配据此排一次「/」指令面板的同步：

## claude-agent 怎么接

claude-agent 是可选注入：没装时 qq-bot 照常加载、能收消息、能回 `/帮助` 与直接命令，任务派不出去，回执写明装哪个插件。`qq-bot.status` 的 `claudeAgentInstalled` 看它此刻在不在。
qq-bot 只用它服务上的四个方法：`create` / `send` 开一轮，`waitRound` 等这一轮结束，`status` 给 `/状态` 读进度。模型、token、轮数上限都是 claude-agent 的设置，换模型改那边的 `default-model`，不经 qq-bot；要从 QQ 换，就在 QQ 里发一条任务，让 agent 去改那项设置。

## 不做的事

- **不选执行端、不选模型**：一律交给 claude-agent，模型是它的设置，见[执行统一交给 claude-agent](/trajectory/2026-10-15-claude-agent-only)
- **不让 agent 调命令回报**：等这一轮结束，直接取它的最后一条回复，见[去掉回报命令](/trajectory/2026-10-15-final-reply-instead-of-report)
- **不自动重发**：派出失败、这一轮失败都把原话告诉人，由人决定要不要再派，见[按聊天重写](/trajectory/2026-10-07-rebuild-around-chats)
- **不锁工作区**：两个组指向同一个目录也同时做，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不做前缀匹配、不设别名，以「/」开头的未知命令不派出**：拼错的命令当场报出来，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不从 QQ 回到旧会话**：在电脑上接，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不写和协作站有关的代码**：协作项目由协作站自己注册任务组，见[协作项目注册任务组](/trajectory/2026-10-08-collab-registers-project-groups)
- **不解析 agent 回答的内容**：最后一条回复原样发回；提示词要求 5000 字以内，超了由连接与收发按 5000 字分段发
