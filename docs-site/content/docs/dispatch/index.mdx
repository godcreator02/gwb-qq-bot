源码在 `plugins/qq-bot/src/dispatch/`。方向是人 → 工作台 → agent → 人：私聊里的一句话交给某个任务组的执行端，agent 做完回报，结果发回原私聊。
`chat-rounds.ts` 是中心，别的文件是它用的纯函数（分发、会话选择、参数校验）、插件注册表和执行端适配层。它只经连接与收发导出的函数收发消息，不 import 通知。

一条消息具体分到哪，做成了可以逐条点的讲解：[一条消息分到哪](/docs/dispatch/routing)。聊天表的形状与迁移在[聊天表](/docs/dispatch/chat-table)。

## 任务组

一个任务组对应一个工作区和一个执行端，在每个私聊里各有一份会话、在做的一轮和队列。同一组一次只做一轮，后来的消息排在这一组自己的队列；不同的组各自排队、可以同时做，两个组指向同一个目录也照样同时做，不锁工作区。

组有三种来源：

| 来源 | 怎么来 | 谁能用 | 存在哪 |
| --- | --- | --- | --- |
| 默认组 | 每个私聊一个，由 `qq-bot.bind` 设；主人私聊没绑时用设置 `default-workspace`、交给 ZCode | 只有这个私聊 | 绑定写在私聊行里，主人的默认绑定按设置现算 |
| 命令登记的组 | agent 调 `qq-bot.group.add` / `remove` | 白名单里的每个私聊 | 聊天表 |
| 插件注册的组 | 别的插件调 `gwbQqBot.registerTaskGroup` | 白名单里的每个私聊 | 服务对象上，插件卸载或重载时撤掉 |

命令登记的组存在聊天表、不放进设置：设置项只支持字符串、数字、布尔与字符串列表，存不下一个组的几个字段，见[组登记存聊天表](/trajectory/2026-10-08-own-groups-in-chat-table)。

## 命令名

命令以 `/` 开头、不含空白，去掉斜杠后汉字等非 ASCII 字符算 2、其余算 1，总长不超过 16，和 QQ 管理端指令名的上限一致，每个命令都放得进 QQ 的「/」面板。
`/帮助`、`/状态`、`/新会话` 是保留命令，谁都不能注册；和已有的任何命令重名（不论对方是哪种来源）直接报错，不覆盖、不自动改名。去掉斜杠就是组名，`/新会话 <组名>` 用它：

{/* ref file="../plugins/qq-bot/src/dispatch/routing.ts" lines="4-10" hash="caa7229e4233" blob="4ba17a7cf705" */}

{/* ref file="../plugins/qq-bot/src/dispatch/routing.ts" lines="72-81" hash="c35789eb79e8" blob="4ba17a7cf705" */}

命令以工作台里注册的为准，`/帮助` 按此刻注册的现算；QQ 的「/」面板只能在管理端手动配置，qq-bot 不同步它，见[不同步「/」面板](/trajectory/2026-10-08-qq-command-panel-not-synced)。

## 会话

下一轮接着用这一组的哪个会话：

- **默认复用**：会话记着执行端和工作区，和组现在的定义对得上、空闲没超时，就接着用
- **空闲超时开新会话**：这一组上一条任务开始或收尾以后，过了组的 `idleHours`（不给就用设置 `idle-hours`，缺省 6）才来下一条，就开新会话，回执里写「已开新会话（空闲超过 N 小时）」
- **换了执行端或工作区开新会话**：改绑、组的定义改了都算
- **手动开新会话**：`/新会话` 清掉默认组的会话，`/新会话 <组名>` 清掉那一组的；在做的那一轮照常回报

{/* ref file="../plugins/qq-bot/src/dispatch/group-session.ts" lines="14-32" hash="3a567abfd36e" blob="df96b60d79d3" */}

设置 `idle-hours` 不是正数时派任务报错、这条不派出，不替它改值。定了开新会话就当场清掉旧的：派出失败以后上一条任务的时间已经刷新，不清的话下一条会接回旧会话：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="214-238" hash="c4b94c679ae8" blob="52997d98cc3c" */}

执行端没接着用交给它的会话、交回了另一个会话号，就算开了新会话，轮数从 1 数起。回执开头写组名，第二行是「会话 a1b2 · 第 3 轮」（会话号的末 4 位、这个会话的第几轮），手机上看得出是接着做还是新开的：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="273-278" hash="84d2e9084e82" blob="52997d98cc3c" */}

旧会话不能从 QQ 回去接着做：它们在 ZCode 或 Claude Code 里还看得到，要接着做就在电脑上接。

## 一轮怎么走

**入队**：收下消息、分发、进这一组的队列在同一步里做完（见[连接与收发](/docs/qq)的去重），然后让这一组往前走：没有在做的一轮就取下一条开一轮；有就回「上一条还在做，这条排在第 N 个」。

**派出**：从这一组的队列取下一条，定下会话，记下本轮编号、发言人、执行端、工作区和触发消息，经执行端适配层的 `start` 派出，拿回会话号存进这一组的状态，回「已接收」。
派出失败就把原话带组名回给私聊、这一轮作废、接着派这一组的下一条，不留「派出未确认」这种要人手工解除的状态——可能已经发出去了的，执行端的原话里会写，人去执行端看。

**提示词**：任务原文后面附三段：来源（QQ 私聊、发言人、任务组的称呼与工作区）、组的要求（组或绑定写了 `instructions` 才有，原样附上）、本轮回报说明。
回报说明写的是 home 名，不写 MCP 服务名：每个 gwb MCP 服务的说明里都写着它连的是哪个 home，agent 照着选，两个 home 各自派出的任务不会报到另一个 home：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="280-295" hash="e6b1a3e4b0bb" blob="52997d98cc3c" */}

**回报**：本轮编号只用来对上是哪一轮，不当凭证，在所有私聊的所有组里找。同一轮同一段话重交回 `duplicate`，已经结束的轮次交来不同的话拒绝，超过 2000 字拒绝；回执先交回，发回 QQ 与开下一轮在后台做，agent 不用等自己的回报发完：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="318-334" hash="d13e5c2bbbbe" blob="52997d98cc3c" */}

**收尾**：结果开头写「【组名 · 第 N 轮】」，引用派出这一轮的那条消息；被动、主动都发不出去，连同要引用的消息 id 和组名记进这个私聊的没送达，等人发 `/状态` 补发。收尾后接着开这一组排队的下一条：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="297-314" hash="140bfa501f7f" blob="52997d98cc3c" */}

**懒检查**：没有后台轮询。这一组这一轮还没回报，而人发了 `/状态` 或又往这一组发了一条消息时，才经适配层的 `check` 问一次执行端；做完了却没回报，就按「执行端这一轮已经结束，没有收到回报」收尾，附上最后的回答末尾 600 字，再开下一轮：

{/* ref file="../plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="178-200" hash="5ddcd7de6203" blob="52997d98cc3c" */}

**`/状态`**：有没送达的结果就只补发它们（被动回复用 `/状态` 这条的窗口，引用当初的任务）；没有就逐组报空闲，或在做第几轮、排队几条，在做的组做一次懒检查，最新回答只给末尾 300 字。

## 服务的两个注册方法

`registerTaskGroup`、`registerCommand` 交回撤掉注册的函数，写法和 `gwbSkills.register` 一样：调用方包在 `ctx.effect` 里，插件卸载或重载时自动撤掉；撤掉旧注册不会撤掉之后同名的新注册。
命令名不合规则、和已有命令重名、工作区不是已存在目录的绝对路径都当场抛异常；不检查执行端装没装，派任务时没装就把原因回给私聊。

## 命令

| 命令 | 参数 | 做什么 |
| --- | --- | --- |
| `qq-bot.bind` | `{chat, workspace, title, agent?, instructions?}` | 设一个私聊的默认组：已存在的目录、装着的执行端（缺省 zcode），`instructions` 原样附进提示词 |
| `qq-bot.unbind` | `{chat}` | 解除默认组的绑定；主人私聊解绑后仍按设置 `default-workspace` 派出 |
| `qq-bot.group.add` | `{command, title, workspace, agent, instructions?, idleHours?}` | 登记一个任务组，存在聊天表里；执行端此刻必须装着 |
| `qq-bot.group.remove` | `{command}` | 只删命令登记的组；插件注册的报错并写明来源 |
| `qq-bot.group.list` | 无 | 全部任务组（默认组按各私聊的绑定列）与直接命令，标明来源 |
| `qq-bot.report` | `{round, text}` | 执行任务的 agent 交这一轮的结果 |

私聊在机器人收到它的第一条消息后才出现在 `qq-bot.status` 里，`bind` 用那里的 `id`（`c2c:<openid>`）。参数只收列出的键，多给、少给、空串都直接报错。
绑定、改绑、解绑只看默认组：默认组还有在做或排队的任务时拒绝，别的组不受影响；改绑后默认组下一条开新会话：

## 不做的事

- **不轮询执行端**：只在人发 `/状态` 或这一组又来消息时问一次，见[按聊天重写](/trajectory/2026-10-07-rebuild-around-chats)
- **不自动重发**：派出失败、执行端中断都把原话告诉人，由人决定要不要再派，见[按聊天重写](/trajectory/2026-10-07-rebuild-around-chats)
- **不锁工作区**：两个组指向同一个目录也同时做，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不做前缀匹配、不设别名，以「/」开头的未知命令不派出**：拼错的命令当场报出来，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不从 QQ 回到旧会话**：在电脑上接，见[按命令分任务组](/trajectory/2026-10-08-slash-command-task-groups)
- **不写和协作站有关的代码**：协作项目由协作站自己注册任务组，见[协作项目注册任务组](/trajectory/2026-10-08-collab-registers-project-groups)
- **不解析 agent 回答的内容**：回报正文原样发回，最多 2000 字，超了让 agent 缩短
