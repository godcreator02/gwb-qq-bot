## 形状

一份表就是一个 `Book`：私聊行、命令登记的任务组、通知去重、近期处理过的消息 id、每条触发消息已用掉的被动回复次数。谁读写哪一项：

| 项 | 谁用 | 上限 |
| --- | --- | --- |
| `chats` | 派任务（绑定、各组状态、没送达）；连接与收发建行 | — |
| `groups` | 派任务（`qq-bot.group.add` 登记的组） | — |
| `notices` | 通知 | — |
| `seen` | 连接与收发（网关重推不重复派出） | 2000 条，超了丢最早的 |
| `replies` | 连接与收发（`msg_seq` 不能重复，次数先记再发） | 500 条消息，超了丢最早的 |

{/* ref file="../plugins/qq-bot/src/storage/chat-table.ts" lines="98-108" hash="5e7a2333235b" blob="85ca3a3dcf0c" */}

一个私聊一行，id 是 `c2c:<openid>`。显式绑定写在 `binding`，设的是默认组；主人私聊的默认绑定按设置现算、不写进来。
行里按组名各记一份状态，默认组的键是空串，一个组第一次有任务时才建出它的那一份：claude-agent 的会话、在做的一轮、队列、上一条任务开始或收尾的时间（算空闲多久用）。
在做的一轮记着 claude-agent 交回的会话号与它那边的轮数，重载后凭这两样接着等这一轮结束；会话号还是空的，就是还在派出。

## 读回与迁移

磁盘上的表是系统边界：形状不对直接报错、停止处理，不按缺省值继续执行。现在是第 4 版，读到旧版时在内存里一版一版迁上来，下次写盘就是第 4 版：

- **第 1 版**还有群聊：去掉群聊那几行，私聊去掉 `scene`，换成第 2 版的行
- **第 2 版**每个私聊只有一份会话与队列：会话、在做的一轮、队列归进默认组，没送达的结果补上组名「默认」，换成第 3 版的行
- 绑定上 `collab` 为 true 的，换成一段任务组要求「先读 gwb 说明书 collab」；qq-bot 里和协作站有关的只剩这一句迁移
- **第 3 版**的会话、绑定、命令登记的组都记着执行端名（ZCode 或 Claude Code）：执行端名去掉，旧会话一律作废（各组下一条开新会话），队列、上一条任务的时间、没送达的结果照留；`zcodeOpenedWorkspaces` 与给回报判重的上一轮结果不再要
- **哪一版里有在做的一轮，就报错停下**：那一轮的结果只有旧执行端交得回来。报错写明先把 qq-bot 装回 0.7.x、等这一轮做完再升级；之后派任务、通知、命令都报这个错，见[执行统一交给 claude-agent](/trajectory/2026-10-15-claude-agent-only)
