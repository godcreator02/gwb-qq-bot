## 形状

一份表就是一个 `Book`：私聊行、命令登记的任务组、通知去重、近期处理过的消息 id、每条触发消息已用掉的被动回复次数、已经让 ZCode 打开过的工作区。谁读写哪一项：

| 项 | 谁用 | 上限 |
| --- | --- | --- |
| `chats` | 派任务（绑定、各组状态、没送达）；连接与收发建行 | — |
| `groups` | 派任务（`qq-bot.group.add` 登记的组） | — |
| `notices` | 通知 | — |
| `seen` | 连接与收发（网关重推不重复派出） | 2000 条，超了丢最早的 |
| `replies` | 连接与收发（`msg_seq` 不能重复，次数先记再发） | 500 条消息，超了丢最早的 |
| `zcodeOpenedWorkspaces` | 派任务的 ZCode 那份执行端实现（每个工作区只让 ZCode 打开一次） | 不设上限，只增不减 |

{/* ref file="../plugins/qq-bot/src/storage/chat-table.ts" lines="103-115" hash="04fb70582b67" blob="27e96639d11f" */}

一个私聊一行，id 是 `c2c:<openid>`。显式绑定写在 `binding`，设的是默认组；主人私聊的默认绑定按设置现算、不写进来。
行里按组名各记一份状态，默认组的键是空串，一个组第一次有任务时才建出它的那一份：会话、在做的一轮、队列、上一轮的结果（同一轮重交回报用它判重）、上一条任务开始或收尾的时间（算空闲多久用）。
没送达的结果按私聊记，每条带组名和要引用的消息 id：

## 读回与迁移

磁盘上的表是系统边界：形状不对直接报错、停止处理，不按缺省值继续执行。现在是第 3 版，读到旧版时在内存里迁成第 3 版，下次写盘就是第 3 版：

- **第 1 版**还有群聊：去掉群聊那几行，私聊去掉 `scene`，换成第 2 版的行
- **第 2 版**每个私聊只有一份会话与队列：会话、在做的一轮、队列、上一轮的结果归进默认组，没送达的结果补上组名「默认」。第 2 版的会话没记工作区，取在做那一轮的、再取绑定的，都没有就不留这个会话；也没记轮数，从这里重新数
- 绑定上 `collab` 为 true 的，换成一段任务组要求「先读 gwb 说明书 collab」；qq-bot 里和协作站有关的只剩这一句迁移
- 第 3 版里可以没有 `zcodeOpenedWorkspaces`：没有就按空列表读（还没让 ZCode 打开过任何工作区），版本号不变；有就必须是字符串列表，否则停止处理。从第 1、2 版迁过来的也是空列表
