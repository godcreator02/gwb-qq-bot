**本页回答**：qq-bot 对外提供什么（服务、命令、设置、QQ 里的指令），一条消息怎么变成一轮任务、结果怎么回来，依赖谁，刻意不做什么。

## 功能

手机 QQ 给机器人发一条私聊 → 腾讯投递到 WebSocket 网关（插件常驻这条出站长连接，心跳、断线退避重连、按消息 id 去重）→
白名单校验 → `/帮助` 这类指令当场回答，其余文本排进**这个聊天**的队列 → 没有在跑的一轮就开一轮，交给聊天绑定的执行端（ZCode 或 Claude Code）→
agent 做完自己调 `qq-bot.report` → 结果按被动回复窗口发回原聊天 → 队列里还有就接着开下一轮。

只处理私聊：每个人用自己的机器人私聊，群里 @ 机器人不处理。一个私聊绑一个工作区和一个执行端，同一个私聊一次只跑一轮；不同私聊各跑各的，绑到同一个目录也会并行。
主人私聊没有显式绑定时，用设置里的默认工作区、交给 ZCode。

### 命令

| 命令 | effect | 用途 |
| --- | --- | --- |
| `qq-bot.status` | read | 连接、各个聊天的绑定、在跑的一轮、排队与没送达的结果、最近被拒的 openid |
| `qq-bot.bind` | write | `{chat, workspace, title, agent?, collab?}`：把一个私聊绑到已存在的目录与装着的执行端；`collab` 为 true 表示协作仓 |
| `qq-bot.unbind` | write | `{chat}`：解除绑定 |
| `qq-bot.report` | external | `{round, text}`：执行任务的 agent 交这一轮的结果 |
| `qq-bot.notify` | external | `{id, text}`：服务方法 `notify` 给 agent 的薄封装 |
| `qq-bot.reconnect` | write | 改完 AppID / AppSecret / 旧沙箱接口设置后重连 |

私聊在机器人收到它的第一条消息后才出现在 `qq-bot.status` 里，`bind` 用那里的 `id`（`c2c:<openid>`）。
绑定、改绑、解绑在这个聊天还有在做或排队的任务时拒绝；改绑后下一轮用新会话。参数与回执的逐条说明在随包说明书 `qq-bot`。

### 设置

`app-id`、`app-secret`（走凭据保管）、`sandbox`（缺省 false，true 只兼容旧沙箱接口），这三项改完要 `qq-bot.reconnect`；
`allowed-openids`（每条消息现读，改完即时生效）、`owner-openid`（主人，主动通知的收件人）、`default-workspace`（主人私聊没绑时的工作区）。

### QQ 里的指令

`/帮助`、`/状态`（补发没送达的结果；没有就报这一轮在做什么，必要时做一次懒检查）、`/新会话`（下一轮起用新会话）。整条精确匹配，其余文本都是任务。

## 一轮怎么走

**派出**：从队列取下一条，记下本轮编号、发言人、执行端、工作区和触发消息，再经执行端适配层的 `start` 派出；拿回会话号存进聊天表，回「已接收」。
派单失败就把原话回给聊天、这一轮作废，不留「派单未确认」这种要人手工解除的状态——可能已经发出去了的，执行端的原话里会写，人去执行端看。

**提示词**：任务原文后面附两段：来源（QQ 私聊、发言人、工作区，协作仓另写一句改动经 `collab.submit` 提交）与本轮回报说明。
回报说明写的是 home 名，不写 MCP 服务名——每个 gwb MCP 服务的说明里都写着它连的是哪个 home，agent 照着选，两个 home 各自派的活不会报到另一个 home：

**回报**：本轮编号只用来对上是哪一轮，不当凭证。同一轮同一段话重交回 `duplicate`，已经结束的轮次交来不同的话拒绝；回执先交回，投递与下一轮在后台做，agent 不用等自己的回报发完：

{/* ref file="../plugins/qq-bot/src/rounds.ts" lines="216-231" hash="8566de8130e5" blob="d5c550bb4d85" */}

**懒检查**：没有后台轮询。这一轮还没回报，而人发了 `/状态` 或又来一条消息时，才经适配层的 `check` 问一次执行端；做完了却没回报，就按「执行端已结束、没有收到回报」收尾，附上最后的回答，再开下一轮：

一个私聊一行。显式绑定写在 `binding`；主人私聊的默认绑定按设置现算、不写进来。会话号随执行端走，换执行端、改绑、`/新会话` 时清空：

{/* ref file="../plugins/qq-bot/src/chats.ts" lines="38-55" hash="8546a9cd8055" blob="cbc1e1e5ddec" */}

整份表按 AppID 存成一份 gwb-data 文档 `chats-<AppID>`，换机器人就是另一份，记录里不写 home 与 AppID。另外记着主人通知的去重、近期处理过的消息 id（网关重推不重复派单）、
每条触发消息已用掉的被动回复次数——`msg_seq` 不能重复，次数先记进表里再发：

{/* ref file="../plugins/qq-bot/src/chats.ts" lines="63-71" hash="4c96fd455d24" blob="cbc1e1e5ddec" */}

所有改表的操作经同一条串行队列；调执行端、发 QQ 消息在队列外面做，一个聊天慢不会卡住别的聊天。磁盘上的表形状不对直接报错，不按缺省值往下跑。

## QQ 协议一层

### 白名单

白名单管的是发私聊的人；名单外的消息静默拒绝、只记日志与 `recentRejected`（最多 10 条），不给探测者任何反馈。
官方 API 给的 openid 每个机器人各不相同、不是 QQ 号，首次配置靠 `recentRejected` 里抄。

### 回复路怎么选

{/* ref file="../plugins/qq-bot/src/reply-window.ts" lines="1-25" hash="9a3354b64365" blob="c063025593d7" */}

窗口与次数是腾讯侧的硬限制（单聊 60 分钟、每条触发消息 4 次），插件只做选择：窗口内、次数没用完走被动回复；窗口外、次数用完或被动发不出去，改发一次主动消息；主动也发不出去，记进没送达、等人发 `/状态` 补发。
测试在 `tests/reply-window.test.ts`。

### 引用原消息

每条回复都带 `message_reference`，在 QQ 里显示成引用它所回答的那条消息：回执引用刚收到的那条，一轮的结果引用派出这一轮的那条，排队、结果交叉出现时也看得出哪条结果对应哪条任务。
「挂在哪条消息上」（`msg_id`，决定被动回复的窗口与次数）和「引用哪条」是两件事：没发出去的结果连同要引用的消息 id 记进没送达，`/状态` 补发时被动回复挂在这条 `/状态` 上，引用的仍是当初那条任务：

{/* ref file="../plugins/qq-bot/src/rounds.ts" lines="242-245" hash="e4df7400cfe1" blob="d5c550bb4d85" */}

引用取不到原消息时照常发正文、只是不带引用（`ignore_get_message_error: true`），结果本身比引用要紧。单聊的被动回复、被动回复引用另一条更早的消息、主动消息带引用，都正常显示成引用（2026-10-07 在机器人 B 上实测）。

### 订阅哪些事件

{/* ref file="../plugins/qq-bot/src/qq-protocol.ts" lines="19-24" hash="705a04f44a90" blob="6a6bf8eff594" */}

单聊事件 `C2C_MESSAGE_CREATE` 在官方的 `GROUP_AND_C2C_EVENT (1 << 25)` 这一位里，订了它群事件也会跟着到达：群事件只记一行事件类型，不进任务；频道事件不订阅。网关在解析和白名单之前记录事件类型，不记录原始载荷。

### REST 与环境

{/* ref file="../plugins/qq-bot/src/qq-rest.ts" hash="60884f70bc28" blob="3a4012a87ac1" */}

鉴权与业务接口用 `api.bot.qq.com`；`sandbox=true` 只兼容旧 `sandbox.api.sgroup.qq.com`。私聊一律发纯文本（`msg_type:0`），回复请求显式转成 `msg_id` / `msg_seq`，业务错误兼容 `err_code` 与 `code`。测试在 `tests/qq-rest.test.ts` 与 `tests/qq-gateway.test.ts`。

## 依赖

| 依赖 | 怎么接 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- |
| `gwbCommands`、`gwbSettings`、`gwbData` | 必需 inject | 命令、设置、聊天表 | 插件不加载 |
| `gwbZcode`（gwb-zcode） | 可选 inject，peer 标 optional | ZCode 那份执行端实现 | 绑定与派单报「没装执行端 zcode」 |
| `gwbClaudecode`（gwb-claudecode） | 可选 inject，peer 标 optional | Claude Code 那份执行端实现 | 同上 |
| `gwbSkills` | 可选 inject | 登记说明书 `qq-bot` | agent 读不到说明书 |
| `cordis` | peer | 服务基类 `Service` | — |
| QQ 开放平台 | 外部服务 | WebSocket 收事件，REST 发消息 | 连不上时网关退避重连 |

{/* ref file="../plugins/qq-bot/src/index.ts" lines="43-43" hash="f3e25754b611" blob="10341bf4c429" */}

qq-bot 不依赖协作站：私聊绑协作仓时，绑的人先用 `collab.projects` 查到协作仓路径与项目名，再带 `collab: true` 绑上。依赖只朝协作站 → qq-bot 一个方向。

## 不做的事

- **不做界面**：状态经 `qq-bot.status` 查
- **不做随手记**（「记：」）：等 gwb-bn-journal 提供往当天日志追加一条的服务后再接
- **不处理群聊**：每个人用自己的机器人私聊，群里 @ 机器人只记事件类型
- **不轮询执行端**：只在人问起时做一次懒检查
- **不自动重发**：派单失败、执行端中断都把原话告诉人，由人决定要不要再派；结果被动发不出去只改发一次主动消息，再不行就等人发 `/状态`
- **不解析 agent 回答的内容**：回报正文原样发回，最多 2000 字，超了让 agent 缩短
