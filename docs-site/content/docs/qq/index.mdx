源码在 `plugins/qq-bot/src/qq/`。这一块只管「和 QQ 怎么收发」：收到的私聊交给装配，发什么由调用方决定，怎么发由这里决定。
它不 import 通知与派任务；那两块经装配传进来的函数、以及这里导出的类用它。

## 功能

### 网关：收私聊

一条出站 WebSocket 长连接：Hello 之后发 Identify 或 Resume，按服务端给的间隔发心跳；两次心跳之间没收到 ACK、连接被关、网关要求重连，都按 1 秒起翻倍、最长 60 秒退避重连，收到 READY 后归零。
只有 4007、4008、4009 三种关闭码接着 Resume，其余重新 Identify：

### 入站两道关：白名单与去重

白名单管的是发私聊的人。名单外的消息静默拒绝、只记日志、最近 10 条被拒的 openid 和消息记录（正文前 40 字），不给探测者任何反馈；名单每条消息现读设置，改了即时生效。
官方 API 给的 openid 每个机器人各不相同、不是 QQ 号，首次配置从 `qq-bot.status` 的 `recentRejected` 里取：

{/* ref file="../plugins/qq-bot/src/qq/incoming-gate.ts" lines="13-21" hash="e1633982638a" blob="da543a94796c" */}

第二道是聊天表里的去重，防的是重载、重连之后网关再推一次：在串行队列里建私聊行、记下消息 id，第一次见到才把同一步交给调用方改表，然后一起存盘。
派任务把分发与入队写在这一步里，所以一条消息不会入队两次：

### 回复：被动还是主动

窗口与次数是腾讯侧的硬限制（单聊 60 分钟、每条触发消息 4 次），这里只做选择：窗口内且次数没用完走被动回复；过了窗口、次数用完或没有触发消息，走主动消息。测试在 `tests/reply-window.test.ts`：

{/* ref file="../plugins/qq-bot/src/qq/reply-window.ts" hash="9a3354b64365" blob="c063025593d7" */}

`ReplySender.reply` 把一段话按行切成 5000 字以内的几段（多段加「(i/n)」；提示词要求最后一条回复在 5000 字以内、通知的上限也是 5000 字，接近 5000 字的结果加上开头「【组名 · 第 n 轮】」那一行才会分成两段；在代码块中间切开会让渲染出错），每段重新选一次路：选了被动就先在聊天表里记一次、存盘再发，`msg_seq` 不会重复；被动发不出去改发一次主动消息；主动也发不出去回 false，由调用方记进没送达：

{/* ref file="../plugins/qq-bot/src/qq/reply-sender.ts" lines="47-65" hash="aa214ba2d732" blob="806a680979b2" */}

### 引用原消息

每条回复都带 `message_reference`，在 QQ 里显示成引用它所回答的那条消息。「被动回复用哪条消息的窗口与次数」（`msg_id`）和「引用哪条」是两个参数：
回执引用刚收到的那条；一轮的结果引用派出这一轮的那条；`/状态` 补发的结果用 `/状态` 这条的窗口，引用的仍是当初那条任务。实测记录见[回复引用原消息](/trajectory/2026-10-07-quote-the-task-message)。

引用取不到原消息时照常发正文、只是不带引用（`ignore_get_message_error: true`），结果本身比引用要紧。

### REST 与 access token

{/* ref file="../plugins/qq-bot/src/qq/qq-rest.ts" lines="101-118" hash="887ba7f69d04" blob="db40ee860471" */}

鉴权与业务接口用 `api.bot.qq.com`；设置 `sandbox` 为 true 时只兼容旧的 `sandbox.api.sgroup.qq.com`。私聊一律发原生 markdown（`msg_type: 2`，正文放在 `markdown.content`）：纯文本（`msg_type: 0`）在手机上原样显示 `##`、反引号这些符号，原生 markdown 才渲染；路径里的反斜杠、下划线、星号实测不会显示错，见[私聊改发原生 markdown](/trajectory/2026-10-15-c2c-native-markdown)。被动回复显式转成 `msg_id` / `msg_seq`；HTTP 200 里业务错误码非零也算失败，错误码同时认 `err_code` 与 `code`。

access token 提前 2 分钟刷新，几个请求同时要时共用一次换取；`qq-bot.reconnect` 时换一个代次，晚回来的旧请求不覆盖新缓存。官方回的 `expires_in` 是数字字符串，数字与字符串两种都收，这是照官方文档核对过的，不是放宽校验：

测试在 `tests/qq-rest.test.ts`。

### 指令面板：跟着注册的命令走

手机 QQ 私聊里打「/」弹出的指令面板，由 `command-panel.ts` 经官方 `/v2/panels` 接口同步成此刻注册的命令。点面板里的一条指令只是把它填进输入框，人接着写任务再发，到达的是普通文本，分发照常认。

**什么时候同步**：插件注册或撤掉任务组、直接命令，`qq-bot.group.add` / `remove` 登记或删掉组，连上 QQ（包括断线重连），都排一次同步。变化停下 2 秒才做，期间再变只重新计时；同一时刻只跑一次，跑着时又变了就跑完再排一次。插件卸载时它的注册已经经它自己的 `ctx.effect` 撤掉，这里只听注册表的变化：

{/* ref file="../plugins/qq-bot/src/qq/command-panel.ts" lines="188-196" hash="22fa6bdad028" blob="a061ff8fbfd0" */}

**放什么**：顺序由派任务给（任务组 → 直接命令 → `/新会话`、`/状态`、`/帮助`，见 `dispatch/panel-candidates.ts`），这里只套官方上限：名字含斜杠超过 14（汉字算 2）的不进面板，说明超过 30 截短、末尾换成「…」，最多 20 条，排在后面的放不下。没放进去的连同原因列在 `qq-bot.status` 的 `panel.omitted` 里，日志记一行。命令名规则（去掉斜杠最长 16）不因面板改变：

{/* ref file="../plugins/qq-bot/src/qq/command-panel.ts" lines="8-22" hash="6aa583a14372" blob="a061ff8fbfd0" */}

{/* ref file="../plugins/qq-bot/src/qq/command-panel.ts" lines="54-72" hash="91f2fba84bca" blob="a061ff8fbfd0" */}

**始终改同一个面板**：备注里写固定标记 `gwb-qq-bot 自动同步`（备注不对用户展示），`GET /v2/panels?scope=c2c` 按标记认出自己的面板。找不到就 `POST` 新建，白名单为空时不建；找到多个留列表里的第一个、其余删掉；条目没变不调 `PUT`。`PUT` 只覆盖条目与备注、不动能看到面板的用户，用户另经 `PUT /v2/panels/{panel_id}/target` 按差集增删。一个面板都没有时，官方的列表实测只回 `{"is_end":true}`，省略 `records` 与 `next_cursor`，按空列表、空串读，这是核对过的契约，不是放宽校验：

{/* ref file="../plugins/qq-bot/src/qq/qq-protocol.ts" lines="102-111" hash="97e660912903" blob="053e274b13f5" */}

{/* ref file="../plugins/qq-bot/src/qq/command-panel.ts" lines="104-136" hash="6160f942edf9" blob="a061ff8fbfd0" */}

**给谁看**：`scope: "c2c"`、`target_type: "specific"`，用户是设置 `allowed-openids` 的前 20 个（建面板时官方单次最多 20 个），超出的列在 `panel.omittedTargets`。设置没有变化通知：每 30 秒在本地现算一次该有的面板，和上次同步时不同才排同步，不调接口。没配 AppID、还没连上时不同步，原因写在 `panel.notSyncing`：

{/* ref file="../plugins/qq-bot/src/index.ts" lines="78-85" hash="70a35eead6bb" blob="20c8b227e0e7" */}

**出错**：「面板操作进行中」（40030009）隔 5 秒重试一次；别的错误、或重试还是进行中，都不再重试，原话记进 `panel.error` 与日志，等下次变化或重连再同步。回执形状不对时报错里带上回执原文的 JSON（最多 500 字，面板接口的回执里没有凭据），对着它核对官方字段：

测试在 `tests/command-panel.test.ts`（条目、按标记增删改、防抖、注册与撤掉、白名单变化、重试与报错），请求形状在 `tests/qq-rest.test.ts`。官方接口文档地址列在仓根 AGENTS.md。

### 消息记录

`message-log.ts` 把机器人收到的每条私聊、发出的每条消息各记一行，`qq-bot.messages` 查。排查「结果发出去没有」「那条消息分到哪了」先查它，不翻 gwb.log。

**存在哪**：qq-bot 在这个 home 里的数据目录（`gwbData.dir`，和聊天表那份文档同一个目录），按机器人、按月各一个 JSONL 文件 `messages-<AppID>-<YYYY-MM>.jsonl`，月份按 UTC 算，只追加。不用 gwb-data 的文档：文档每次整份重写，不适合一直增长的东西。连上机器人时建出记录对象并清理一次旧文件：

{/* ref file="../plugins/qq-bot/src/index.ts" lines="134-136" hash="226b180a9194" blob="20c8b227e0e7" */}

**谁来记**：所有入站与出站都经过这个目录，记录也只在这里写；可这个目录不认识任务组，「分到哪」「是哪一种出站、哪个组、第几轮」由调用方作为参数传进来。白名单外的由白名单记；收下的由派任务算好分到哪再记，空消息、聊天表判出的重复投递也各记一条（同一条连接里网关自己去重丢掉的不记）：

{/* ref file="../plugins/qq-bot/src/qq/message-log.ts" lines="46-53" hash="b4e0fcf23f21" blob="1b247976864d" */}

出站不靠每个调用方记得去记：接线把 `QqRestClient.sendC2c` 交给 `recordingSend` 包一层，包出来的才交给发回复与通知，每次发完（成功、官方回失败、抛错）记一条再原样交回。`ReplySender.reply` 多一个用途参数，加上第几段传下去，所以分段发送的每段各一条；被动发不出去改发主动时也是两条：

{/* ref file="../plugins/qq-bot/src/rounds.ts" lines="44-50" hash="6bc7e091a12d" blob="b6110e59a544" */}

**记什么**：每条有时间、方向、私聊 id（`c2c:<openid>`，和 `qq-bot.status` 的相同）与消息 id。入站记正文全文与分到哪；白名单外的只记正文前 40 字、标明被拒，不给探测者的话留全文。出站记正文全文、种类、组名与本轮编号（有的才有）、被动（回复的是哪条消息、`msg_seq`）还是主动、引用的消息、第几段、结果（成功带发出去的消息 id，失败带官方错误码与原话）：

{/* ref file="../plugins/qq-bot/src/qq/message-log.ts" lines="64-79" hash="1cbd47593834" blob="1b247976864d" */}

出站种类按代码里实际有的出站定，一共六种：

{/* ref file="../plugins/qq-bot/src/qq/message-log.ts" lines="11-24" hash="c1b1475362fc" blob="f01dd82e33b7" */}

**写失败不影响收发**：写入排成一条队按顺序做，收发不等它；写失败只记一行 warn（不带正文），这是有意的降级，记录是旁路。测试在 `tests/message-log.test.ts`（按月分文件、清理、写失败、发送抛错、查询）与 `tests/rounds.test.ts` 的「消息记录」（入站、被拒、没派出的原因、出站成功与失败、分段、通知、补发）：

**保留**：当月与前 3 个月的文件留着，更早的删掉（所有机器人的都算），删了几个记一行日志。连上时清理一次，记录跨进新的月份时再清理一次，不另开定时器：

{/* ref file="../plugins/qq-bot/src/qq/message-log.ts" lines="173-184" hash="2f5c52fc5ba0" blob="1b247976864d" */}

**查询**：`qq-bot.messages` 按设置 `app-id` 那个机器人查，不要求连着，没配 AppID 回空列表；查之前先等排着的写入做完。从最新的月份倒着读、按条件筛，找够 `limit` 条就停，`more` 说明还有更早的。回执超过 MCP 单次 40000 字（按两格缩进的 JSON 算）就报错，让调用方把 `limit` 改小或加条件，不截断。文件里有读不懂的行也报错，指出哪个文件第几行：

{/* ref file="../plugins/qq-bot/src/qq/message-log.ts" lines="283-312" hash="2ead2772be9a" blob="1b247976864d" */}

**为什么不进 gwb.log**：gwb.log 是这个 home 里内核、插件、页面共用的日志，正文进去就和别的插件的日志混在一起，没法按私聊、组、轮次查，也没法单独清理。所以 gwb.log 里照旧只有事件类型、序号、openid 与报错，正文只进消息记录。取舍见[消息记录单独存](/trajectory/2026-10-08-qq-message-log)。

## 接口

这一块对外给的就是这些，调用方都在插件里：

| 导出 | 文件 | 谁用 |
| --- | --- | --- |
| `QqGateway`（`start` / `stop` / `currentState`，回调 `onMessage` / `onState`） | `qq-gateway.ts` | 装配建出、重连时停掉重开 |
| `QqRestClient`（`sendC2c` / `getAccessToken` / `resetAuth` / `fetchGatewayUrl`，指令面板的 `listC2cPanels` / `createC2cPanel` / `updatePanel` / `deletePanel` / `panelOpenids` / `changePanelTargets`）、`QqApiError` | `qq-rest.ts` | 装配建出；`sendC2c` 作为发消息的函数传给通知与回复；面板那几个交给 `CommandPanelSync` |
| `CommandPanelSync`（`schedule` / `startWatching` / `status` / `dispose`）、`planPanelItems`、`PANEL_MAX_OPENIDS`、类型 `PanelCandidate` | `command-panel.ts` | 装配建出、排同步、给 `qq-bot.status`；派任务只用类型 `PanelCandidate` |
| `AllowedSenderGate`、`intakeFirstDelivery` | `incoming-gate.ts` | 接线过白名单；派任务收下消息 |
| `ReplySender` | `reply-sender.ts` | 接线建出、交给派任务 |
| `MessageLog`（`inbound` / `rejected` / `recordingSend` / `prune` / `settle`）、`queryMessages`、`parseMessageQuery`，类型 `SendC2c`、`RawSendC2c`、`OutboundPurpose`、`InboundRoute` | `message-log.ts` | 插件入口建出、给 `qq-bot.messages` 查；接线用它包发消息的函数；派任务记入站、给出站写用途；通知只用类型 |
| `chooseReplyRoute` | `reply-window.ts` | `ReplySender` |
| `IncomingMessage`、`QqLog`、`isRecord` 与协议常量 | `qq-protocol.ts` | 全插件 |

协议字段名、事件位值都集中在 `qq-protocol.ts`，接口报错先对官方文档（地址列在仓根 AGENTS.md）核对再改这里。

## 依赖

QQ 开放平台（网关、发消息与指令面板的 REST 接口）；聊天表（近期消息 id、被动回复次数，都在串行队列里改）；消息记录写进的数据目录。不依赖 gwb 的任何服务：凭据与沙箱开关由装配经函数传进来，每次现读；数据目录的路径也由装配传进来。

## 不做的事

- **不处理群聊**：群事件只记事件类型，不解析、不回消息，见[只处理私聊](/trajectory/2026-10-07-private-chat-only)
- **不重发**：被动发不出去只改发一次主动消息，再不行交给调用方记没送达
- **不删指令面板**：qq-bot 卸载、断开时面板留着，下次连上接着改同一个，见[自动同步「/」面板](/trajectory/2026-10-08-qq-command-panel-auto-sync)
- **gwb.log 里不记原始载荷与正文、哪里都不记凭据**：gwb.log 里只有事件类型、序号与 openid，消息正文只进消息记录；access token 与 AppSecret 不进日志、不进消息记录、不进命令回执，见[消息记录单独存](/trajectory/2026-10-08-qq-message-log)
