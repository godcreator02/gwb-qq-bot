`node probe.mjs`

## 问什么

两个机器人能否完成指令面板、停用入群策略的新建、读取、修改与清理，以及菜单同值写入、分享链接生成？

## 怎么运行

在本目录运行第一行命令；Node.js 24，零第三方依赖。`api.mjs`、`input/targets.json` 都是本实验内的固定副本，不依赖其他实验或仓的 node_modules。凭据按 AppID 校验后从 `%APPDATA%/gwb-kernel/homes` 本地读取，可由 `QQ_PROBE_HOMES_ROOT` 指定，不复制进仓、不输出令牌。

只在群面板原本为空时创建绑定测试群的新面板；结束时只删除本次创建的面板 ID。新建审批策略明确 `is_enable=off`，白名单仅用当前机器人公开分享链接里的机器人 QQ 号，增后即删，不执行审批。全局菜单只回写查询所得的相同内容并复核内容相等。每次写入和清理回执都保存在独立 `runs/*.json`。若清理失败退出 2，不能当完成。

## 结论

首轮 `runs/2026-10-05T174432-979Z.json` 共 40 次请求，全部 HTTP 200。两端新面板完成创建、读取、更新、目标删除/添加、删除；停用策略完成创建、修改、白名单增删、删除；分享链接生成成功。4 条资源清理回执全部成功，随后列表恢复为空；两个菜单回写后内容相等。success 只表示该请求成功；同值菜单写入不证明任意菜单内容或客户端交互通过。策略执行与真实入群审批未测。
