# 问什么

QQ 官方机器人的**主动消息**（不带 msg_id 的单聊）在沙箱环境、收发双方处于活跃交互期时，
连发有没有条数限制？网上流传「每月每用户 4 条」，官方接口文档原文写的是发送方 10 QPS（个人认证）、
接收方每天 1000 条——哪个是真的？

# 怎么运行

```
node probe.mjs <appId> <收件人openid> [条数=8]
```

前提：default home 的凭据保管里有 `qq-bot` 分区的 `app-secret`（脚本自己读，不回显）。
收件人 openid 得是该机器人的白名单/测试用户，且近期与机器人对话过（处于活跃交互期）。

# 结论

2026-10-05 实测：连发 8 条（间隔 600ms）**全部 HTTP 200**，每条返回消息 id，无一条被拒。
与接口文档原文的频控（发送方 10 QPS、接收方每天 1000 条）一致；「每月每用户 4 条」是搜索摘要把
「互动召回消息 30 天 4 周期各 1 条」误传成了普通主动消息的配额。普通主动消息与互动召回
（is_wakeup 字段）是两个机制，本项目只用前者。

边界：只测了沙箱环境 + 活跃交互期；30 天不交互后的冷启动情况、正式环境未测。
