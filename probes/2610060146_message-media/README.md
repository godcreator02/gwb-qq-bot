`node probe.mjs`

## 问什么

在当前两个机器人与已确认的测试群/主人私聊中，官方消息、URL 媒体上传、分片上传和撤回接口是否能用有效参数完成调用？

## 怎么运行

在本目录运行第一行命令，Node.js 24，零外部依赖。目录内 `api.mjs`、目标清单与 `fixture.txt` 为独立固定输入，不导入仓源码或其他实验。凭据由 `QQ_PROBE_HOMES_ROOT` 或默认本机 home 读取并校验 AppID，不记录明文。

会向配置的主人私聊与测试群发送带 QQ-API-PROBE 标记的文本、Markdown 和机器人自身头像；只撤回本轮接口返回的消息 ID。分片上传只使用本目录无害文本，不上传本机其他文件；凭据和预签名 URL 不进入记录。流式接口尝试无 msg_id 的单片结束请求，若平台要求被动消息则记录失败，不能据此断言有效被动窗口内不可用。分片链路没有返回真实 upload_id 时停止，不能编造参数去制造错误。每轮结果追加到 runs。

## 结论

首轮 `runs/2026-10-05T174639-070Z.json` 共 50 次请求（含 4 次预签名分片 PUT）；48 次 HTTP 200。A/B 的群聊和私聊均完成文本、Markdown、头像图片发送及本轮消息撤回，12 条撤回回执全部成功；4 条分片准备→PUT→分片完成→合并链路成功。两端单聊流式请求均返回 HTTP 500、`50015001`（系统繁忙），本轮未提供 msg_id，不能证明有效被动窗口内也会失败。未发送合并后的文本文件；没有公开的上传对象删除接口，因此只确认消息撤回，不声称平台缓存文件已删除。HTTP 200 不代表客户端渲染或机器人互相触发成功。
